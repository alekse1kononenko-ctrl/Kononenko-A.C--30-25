# Эмулятор оболочки ОС — вариант 13

Практическая работа по дисциплине «Конфигурационное управление»,
группа ИКБО-30-25. Требования варианта находятся на страницах 44–46
методички. Эмулятор работает в консоли и выполняет команды из задания.

Весь код написан на функциях, словарях, списках и циклах.
Собственных классов, наследования и внешних библиотек нет.
ZIP читается в память, без распаковки. Команда `rm` меняет только
словарь файлов текущей сессии. Архив на диске остается прежним.

## Быстрый запуск

Нужен Python 3.10 или новее. Собирать проект и устанавливать пакеты
не требуется. Команды выполняются из папки `pract1_variant13`:

```sh
python3 scripts/create_vfs.py
python3 -m src.main --vfs data/deep.zip
```

В Windows используйте `python` вместо `python3`.
Генератор создает учебные архивы в папке `data`.
В репозиторий архивы не добавляются, поскольку методичка запрещает
хранить сгенерированные и бинарные файлы.

Оболочку также запускают через `./run.sh --vfs data/deep.zip`
в Linux/macOS или `run.bat --vfs data/deep.zip` в Windows.
Переменная `PYTHON_EXE` позволяет задать путь к интерпретатору.

## Настройки и стартовый скрипт

| Параметр | Назначение |
| --- | --- |
| `--vfs путь` | Обязательный путь к ZIP с виртуальными файлами |
| `--script путь` | Необязательный путь к стартовому скрипту UTF-8 |

При запуске печатаются оба параметра и количество загруженных файлов
и каталогов. Имя архива без расширения становится именем VFS
в приглашении: `deep:/$ `. Путь в приглашении меняется после `cd`.
Физические пути с пробелами передавайте в кавычках.

```sh
python3 -m src.main --vfs data/deep.zip --script scripts/stage5_ok.txt
```

Скрипт содержит по одной команде на строку. Пустые строки пропускаются.
Каждая команда показывается с приглашением, затем появляется ее вывод.
Первая ошибка останавливает скрипт и сообщает номер строки.
После успешного скрипта без `exit` начинается ввод с клавиатуры.
`exit` в скрипте завершает сессию и пропускает оставшиеся строки.

Код завершения: `0` — успешный запуск, `1` — ошибка загрузки или скрипта,
`2` — неправильные параметры запуска. В интерактивном режиме ошибка
отдельной команды позволяет продолжить ввод.

## Команды

| Команда | Что делает |
| --- | --- |
| `ls [путь ...]` | Показывает текущую папку, указанные папки или файлы |
| `cd [путь]` | Меняет папку; без пути переходит в корень VFS |
| `uname` | Печатает имя эмулируемой системы: `UnixEmulator` |
| `cat файл ...` | Печатает текст; двоичные данные показывает как base64 |
| `clear` | Отправляет ANSI-последовательность очистки экрана |
| `rm файл ...` | Удаляет один или несколько файлов из памяти |
| `exit` | Завершает работу |

Пути могут быть абсолютными или относительными. Поддерживаются `.`
и `..`. Переход выше корня оставляет пользователя в корне VFS.
Опции вроде `ls -l` и `rm -r` не реализованы. Каталоги удалять нельзя.
`uname`, `clear` и `exit` не принимают аргументов. Несколько файлов
обрабатываются слева направо до первой ошибки.

Пример работы после загрузки `data/deep.zip`:

```text
ls /
cd /docs/level2/level3
cat note.txt
cd ..
cd .
cd
cat "/docs/file with spaces.txt"
cat /binary.bin
rm /tmp/delete_me.txt /tmp/second.txt
ls /tmp
uname
clear
exit
```

Примеры ошибок: `unknown`, `cd /missing`, `cat /docs`, `rm /docs`.

## Переменные и кавычки

`$NAME` и `${NAME}` подставляют переменные реальной ОС.
Например, `cd "$PR13_DIR"` использует значение `PR13_DIR`.
Неизвестное имя заменяется пустой строкой. Без кавычек пробелы
в значении разделяют аргументы. Двойные кавычки сохраняют значение
одним аргументом. Одинарные кавычки и `\$` запрещают подстановку.
Незакрытая кавычка или `${NAME` приводит к ошибке.
Значение переменной должно указывать на виртуальный путь: физическая
домашняя папка из `$HOME` не обязана существовать внутри ZIP.

В Linux/macOS переменная задается так:

```sh
export PR13_DIR=/docs
python3 -m src.main --vfs data/deep.zip --script scripts/stage4_ok.txt
```

В Windows CMD: `set "PR13_DIR=/docs"`.
В PowerShell: `$env:PR13_DIR = '/docs'`.

## Как читать исходники

Сначала откройте `src/main.py`. Он получает параметры, загружает VFS,
создает сессию и запускает скрипт или диалог. Затем прочитайте
`src/shell.py`: строка проходит через `parse_command`, имя команды
выбирается обычным `if/elif`, соответствующая функция выполняет действие.

VFS — это словарь с двумя ключами:

```python
vfs = {
    "directories": {"/", "/docs"},
    "files": {"/docs/note.txt": "SGVsbG8="},
}
```

`directories` содержит множество путей папок. `files` сопоставляет
путь файла его содержимому в base64. Строка `SGVsbG8=` означает `Hello`.
Сессия хранит имя VFS (`name`), VFS (`vfs`), текущий путь (`cwd`),
признак работы (`running`) и функцию вывода (`write`). Обычно `write`
равна `print`; тесты передают `output.append`, чтобы проверить вывод.

| Модуль | Функции |
| --- | --- |
| `main.py` | `read_settings` читает параметры; `main` запускает программу |
| `parser.py` | `read_variable` читает имя и значение переменной; `escape_value` сохраняет буквальные кавычки; `expand_variables` делает подстановку; `parse_command` разделяет строку стандартным `shlex` |
| `vfs.py` | `resolve_path` нормализует путь; `add_entry` добавляет элемент ZIP; `load_vfs` загружает архив; `check_directory` и `check_file` проверяют путь; `list_path` перечисляет имена; `read_file` читает байты; `remove_file` удаляет запись |
| `shell.py` | `create_shell` создает словарь сессии; `get_prompt` формирует приглашение; `run_command` выбирает команду; `execute` обрабатывает строку и ошибки; `run_script` читает сценарий; `repl` повторяет ввод |
| `commands.py` | `no_options` проверяет аргументы; `list_command`, `cd_command`, `uname_command`, `cat_command`, `clear_command`, `rm_command` выполняют команды |

Константы `UNIX_NAME`, `CLEAR_SEQUENCE`, `ONE_PATH` задают имя системы,
код очистки и ограничение количества путей. `VARIABLE` описывает
допустимое имя переменной. Все функции снабжены docstring.

## Проверка

```sh
python3 -m tests
```

Можно использовать и прежнюю команду:

```sh
python3 -m unittest discover -s tests -v
```

Тесты — обычные функции с `assert`. Стандартный `unittest` запускает их
через готовый `FunctionTestCase`, поэтому свои классы и `setUp` не нужны.
Проверяются команды, переменные, ошибки, скрипты, вложенность каталогов
и неизменность ZIP после загрузки и удаления.

Проверочные скрипты ОС находятся в `scripts`:

- `check_parameters` проверяет оба параметра, пробелы в путях и ошибки.
- `check_vfs` проверяет минимальную VFS, несколько файлов, три уровня
  каталогов, отсутствующий архив и неверный формат.
- `check_commands` проверяет команды, удаление и ошибочные вызовы.

Для каждого есть `.sh`, `.bat` и `.ps1`. В Linux/macOS запускайте
`./scripts/check_parameters.sh`, `./scripts/check_vfs.sh` и
`./scripts/check_commands.sh`. В Windows сначала выполните
`python scripts/create_vfs.py`, затем нужный BAT или PowerShell скрипт.

`scripts/create_vfs.py`: `save_archive` записывает учебный ZIP;
`main` создает `minimal.zip`, `several.zip`, `deep.zip`, архив с пробелами
в имени и файл неверного формата. `ROOT` и `DATA` задают папку проекта
и папку с генерируемыми данными.

Сценарии `stage4_ok.txt` и `stage5_ok.txt` показывают основные команды
и удаление. Ошибки вынесены в `scripts/errors/*.txt`, поскольку первая
ошибка прерывает выполнение. Старые сценарии этапов 2–3 сохранены
для просмотра соответствующих этапов истории. В текущей версии
используйте `vfs_smoke.txt`, `stage4_ok.txt`, `stage5_ok.txt`.

## Этапы работы

История сохраняет пять этапов: REPL с заглушками, настройку,
загрузку ZIP, основные команды и удаление. После них отдельный коммит
упрощает окончательную реализацию. Сообщения новых коммитов имеют вид
`type(scope): описание`, например `refactor(shell): simplify variant 13`.
