# Эмулятор оболочки ОС Вариант 13

Практическая работа по дисциплине «Конфигурационное управление»,
группа ИКБО-30-25. Реализованы пять этапов варианта 13.
Консольная оболочка выполняет только команды задания. Все операции
с VFS происходят в памяти. ZIP не распаковывается и не изменяется.

## Подготовка и запуск

Требуется Python 3.10 или новее. Используется стандартная библиотека;
сборка и установка внешних зависимостей не нужны.

```text
python scripts/create_vfs.py
python -m src.main --vfs data/deep.zip
python -m unittest discover -s tests -v
```

Windows: `run.bat --vfs data/deep.zip`. При нестандартном расположении
Python укажите путь в переменной окружения `PYTHON_EXE`.
`--vfs` задает физический путь ZIP и обязателен. `--script` задает
необязательный стартовый сценарий UTF-8. Оба параметра печатаются
при запуске. Пути с пробелами передавайте в кавычках.

```text
python -m src.main --vfs data/deep.zip --script scripts/stage4_ok.txt
python -m src.main --vfs data/deep.zip --script scripts/stage5_ok.txt
```

Для сценария stage4_ok задайте переменную реальной ОС `PR13_DIR=/docs`.
Она задается в проверочных BAT и PowerShell скриптах автоматически.
Стартовый сценарий показывает каждую команду с приглашением и ее вывод.
Первая ошибка останавливает запуск с кодом 1. Успешный сценарий без
exit переводит оболочку в REPL. Ошибка параметров дает код 2.

## Команды и примеры

| Команда | Назначение и поддерживаемые режимы |
| --- | --- |
| `ls [путь ...]` | Текущий каталог, указанные каталоги или файлы |
| `cd [путь]` | Абсолютный/относительный путь, `.`, `..`; без пути корень |
| `uname` | Имя эмулируемой системы `UnixEmulator` |
| `cat файл ...` | Один/несколько UTF-8 файлов; двоичные данные как base64 |
| `clear` | Очистка ANSI-терминала и перенос курсора в начало |
| `rm файл ...` | Удаление одного/нескольких файлов только в памяти |
| `exit` | Завершение сессии без аргументов |

Опции команд не реализуются: в задании варианта они не перечислены.
rm отклоняет каталоги. Неизвестные команды и неверные аргументы дают
ошибку. Удаленные файлы возвращаются при повторной загрузке ZIP.
При нескольких путях команда обрабатывает их слева направо до ошибки.

```text
ls /
cd /docs/level2/level3
cat note.txt
cd ..
cd
cat "/docs/file with spaces.txt"
rm /tmp/delete_me.txt /tmp/second.txt
exit
```

Парсер раскрывает `$NAME` и `${NAME}` из реального окружения.
Неизвестная переменная имеет пустое значение. В двойных кавычках
подстановка сохраняется одним аргументом; без кавычек пробелы разделяют
слова. Одинарные кавычки запрещают подстановку. Обратная косая черта
экранирует следующий символ. Ошибочные кавычки и скобки отклоняются.

## Проверочные сценарии

`scripts/create_vfs.py` создает minimal.zip, several.zip и deep.zip
с тремя уровнями каталогов; также ZIP с пробелами в имени и неверный ZIP.
Генерируемая папка data игнорируется Git по правилам тетради.

`scripts/check_parameters.bat` и `.ps1` проверяют оба параметра,
пробелы в путях, отсутствие обязательного параметра, отсутствующий
скрипт и остановку на первой ошибке.
`scripts/check_vfs.bat` и `.ps1` проверяют три варианта VFS,
отсутствующий и неверный архивы.
`scripts/check_commands.bat` и `.ps1` проверяют команды и ошибки.
Скрипты stage2 и stage3 сохранены для соответствующих коммитов.
В окончательной версии используйте vfs_smoke, stage4 и stage5.
Независимые ошибочные команды вынесены в `scripts/errors/*.txt`:
после ошибки следующие строки сценария не выполняются.

## Функции и структура

`src/parser.py`: read_variable читает имя переменной; escaped_character
читает экранированный символ; append_unquoted разделяет подстановку;
read_plain обрабатывает обычный символ; parse_command разбирает строку.
ParseState хранит состояние; consume читает символ, expand подставляет
значение переменной. Его __init__ задает начальное состояние.

`src/vfs.py`: VirtualFileSystem.__init__ создает корень; load читает ZIP;
add_entry добавляет элемент; resolve нормализует путь; require_directory
проверяет каталог; list_path перечисляет имена; read_file декодирует
байты; remove_file удаляет запись из памяти.

`src/shell.py`: Shell.__init__ создает сессию; prompt формирует
приглашение; execute разбирает строку и обрабатывает ошибки;
dispatch выбирает команду; run_script выполняет стартовый сценарий;
repl организует интерактивный диалог.

`src/commands.py`: no_options проверяет отсутствие опций;
list_command, cd_command, cat_command, uname_command, clear_command,
rm_command реализуют соответствующие команды. COMMANDS связывает
названия с функциями; UNIX_NAME задает имя системы; CLEAR_SEQUENCE
содержит ANSI-код; MAX_CD_ARGUMENTS ограничивает количество путей cd.

`src/main.py`: read_settings читает параметры; main загружает VFS,
выполняет сценарий и запускает диалог. tests содержит unittest проверки.
`run.bat` запускает оболочку; переменная PYTHON_EXE задает Python.

## История этапов

Пять последовательных Conventional Commits сохраняют REPL,
конфигурацию, VFS, основные команды и rm. Первый и второй коммиты
содержат заглушки ls/cd; в четвертом коммите подключена их логика.
