# Домашнее задание. Вариант 13

Конфигурационное управление. ИКБО-30-25.

## 1. Общее описание

Программа переводит учебный конфигурационный язык в TOML 1.0.
Вход поступает из стандартного ввода (stdin), результат - в стандартный
вывод (stdout). Ошибки поступают в stderr и содержат строку и столбец.
До успешной обработки всего документа TOML не выводится.

Синтаксический анализ выполняет специализированная библиотека
Lark 1.3.1 с алгоритмом LALR(1); грамматика вынесена в отдельный файл.
Значения вычисляются обходом дерева Lark, сериализация выполняется
Tomli-W 1.2.0. Результат в тестах независимо читается через tomllib.

Репозиторий:
[Kononenko-A.C--30-25](https://github.com/alekse1kononenko-ctrl/Kononenko-A.C--30-25).
Все файлы этой работы находятся в `pract3_variant13`.

## 2. Возможности, синтаксис и настройки

### Конструкции варианта 13

| Конструкция | Синтаксис и поведение |
| --- | --- |
| Однострочный комментарий | Апостроф `'` начинает комментарий до конца строки. |
| Многострочный комментарий | `<!-- текст -->`, в том числе с переносами строк. |
| Число | `[+-]?\d+\.\d+`: `1.0`, `+12.5`, `-0.25`. |
| Строка | `[[Это строка]]`, содержимое сохраняется буквально. |
| Массив | `{1.0, [[строка]], {2.0}}`; допустим пустой `{}`. |
| Имя | `[a-zA-Z]+`, только латинские буквы, регистр различается. |
| Объявление константы | `имя: значение;`, каждое объявление создает ключ TOML. |
| Выражение | `$операция левый правый$`, операция стоит перед операндами. |

Массивы и выражения могут вкладываться друг в друга. Массивы допускают
разные типы элементов. Пробелы, табуляция, переносы строк и комментарии
между токенами игнорируются. Внутри `[[...]]` маркеры комментариев,
кавычки и обратные слеши остаются текстом. `]]` завершает строку;
специальной escape-последовательности для этого разделителя нет.

### Константы и операции

Объявления вычисляются сверху вниз. В выражении можно использовать имя,
объявленное раньше. Неизвестное имя, ссылка вперед, ссылка на себя
и повторное объявление считаются ошибками. Таблица констант создается
заново для каждого документа; ключи TOML сохраняют порядок объявлений.
Арифметические операции принимают только числовые значения.

| Операция | Пример | Результат |
| --- | --- | --- |
| Сложение | `$+ 8.0 2$` | `10.0` |
| Вычитание | `$- 8.0 2$` | `6.0` |
| Умножение | `$* 8.0 2$` | `16.0` |
| Деление | `$/ 8.0 2$` | `4.0` |
| Возведение в степень | `$pow 8.0 2$` | `64.0` |

Пример вложенного выражения: `$* 2 $+ 3 4$$` дает `14.0`.

В тетради регулярное выражение чисел требует дробную часть, но пример
константного выражения содержит целое `1`: `$+ имя 1$`.
Поэтому целые литералы разрешены только внутри выражений.
Объявление `x: 1;` отклоняется, `x: 1.0;` принимается.
Обозначение `pow()` в перечне функций реализовано как бинарная
префиксная операция `$pow основание показатель$` по форме примера тетради.
Это уточнения реализации там, где тетрадь не задает полную грамматику.

### Настройки и ограничения

| Параметр | Значение |
| --- | --- |
| Версия Python | 3.11 или новее. |
| Зависимости | `lark==1.3.1`, `tomli-w==1.2.0`. |
| Кодировка потоков | UTF-8; переносы внутри строк сохраняются. |
| Числовой тип | Python float, двоичная арифметика с плавающей точкой. |
| Максимальная вложенность | 64 уровня массивов и выражений суммарно, `MAX_NESTING`. |
| Настройка запуска | `PYTHON` выбирает интерпретатор для `run.sh`. |
| Настройка установки | `make setup PYTHON=python3.12` выбирает Python для окружения. |
| Код завершения 0 | Успех, справка или версия. |
| Код завершения 1 | Ошибка языка, вычисления, кодировки или ввода/вывода. |
| Код завершения 2 | Неизвестный аргумент CLI. |

Вещественные вычисления могут округляться, например при работе с `0.1`.
Деление на ноль, переполнение и невещественный результат `pow`
диагностируются. Бесконечные числа и NaN не выводятся.
Ограничение вложенности задано в реализации для понятной диагностики
вместо переполнения стека. Вложенные многострочные комментарии
не поддерживаются; первый `-->` завершает комментарий.

### Функции исходного кода

Пути далее указаны относительно `pract3_variant13/src`.

| Файл, функция или метод | Назначение |
| --- | --- |
| `parser.py:language_parser()` | Загружает грамматику и кэширует экземпляр Lark. |
| `parser.py:parse(source)` | Разбирает весь вход и сообщает позицию ошибки. |
| `errors.py:TranslationError.__init__()` | Создает ошибку с сообщением, строкой и столбцом. |
| `errors.py:located_error(message, node)` | Берет координаты из дерева или токена Lark. |
| `arithmetic.py:finite_number(value, node)` | Проверяет конечность числового значения. |
| `arithmetic.py:calculate(operation, left, right, node)` | Выполняет одну из пяти операций. |
| `evaluator.py:check_nesting(tree)` | Проверяет глубину дерева до вычисления. |
| `evaluator.py:Evaluator.__init__()` | Создает независимую таблицу констант. |
| `evaluator.py:Evaluator.start(tree)` | Вычисляет объявления в исходном порядке. |
| `evaluator.py:Evaluator.declaration(tree)` | Добавляет константу, запрещает повторы. |
| `evaluator.py:Evaluator.number(tree)` | Преобразует числовой токен в float. |
| `evaluator.py:Evaluator.string(tree)` | Удаляет только внешние `[[` и `]]`. |
| `evaluator.py:Evaluator.array(tree)` | Вычисляет все элементы массива. |
| `evaluator.py:Evaluator.reference(tree)` | Ищет ранее объявленную константу. |
| `evaluator.py:Evaluator.expression(tree)` | Вычисляет операнды и применяет операцию. |
| `evaluator.py:evaluate(tree)` | Проверяет глубину и запускает новый Evaluator. |
| `translator.py:translate(source)` | Разбирает, вычисляет и возвращает строку TOML. |
| `main.py:run(input_stream, output_stream, error_stream)` | Выполняет перевод и возвращает код завершения. |
| `main.py:configure_streams()` | Настраивает UTF-8 и сохранение переносов. |
| `main.py:main(argv=None)` | Обрабатывает CLI и передает стандартные потоки в run. |

Внешняя точка входа для программного использования:

```python
from src.translator import translate

result = translate("base: 2.0; total: $pow base 3$;")
print(result)
```

Результат:

```toml
base = 2.0
total = 8.0
```

## 3. Установка, сборка и тестирование

### Установка на macOS

Нужен Python 3.11+. Проверка: `python3 --version`.
Если версия старее, установите Python 3.11 или новее.
Команды ниже вводятся в приложении «Терминал».
Открыть его можно через Spotlight: Command + пробел, затем «Терминал».

Получить проект:

```sh
cd ~/Documents
git clone https://github.com/alekse1kononenko-ctrl/Kononenko-A.C--30-25.git
cd Kononenko-A.C--30-25/pract3_variant13
```

Создать окружение и установить зависимости:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Если доступен `make`, эквивалентная команда установки:

```sh
make setup
```

Активация окружения не нужна: команды явно используют его Python.
После установки для запуска и тестов интернет не нужен.
Если `python3` указывает на старую версию, используйте установленный
`python3.12` вместо `python3`, в том числе в команде создания окружения.

### Проверка проекта

Отдельной компиляции программы на Python не требуется.
Проверка компилируемости исходников и тестов:

```sh
.venv/bin/python -m compileall -q src tests
```

Запуск всех тестов:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Команды Makefile: `make check`, `make test`, `make examples`.
`make run` читает конфигурацию из stdin, завершение ручного ввода - Ctrl+D.
`compileall` создает только игнорируемые каталоги `__pycache__`.
В репозиторий окружение, кэши, PDF и результаты запусков не добавляются.

## 4. Примеры использования

Все команды выполняются из `pract3_variant13`.

Справка и версия:

```sh
./run.sh --help
./run.sh --version
```

При необходимости скрипт также запускается как `sh run.sh`.
Путь к входному файлу не является аргументом программы: оператор `<`
подключает файл к стандартному вводу. Оператор `>` сохраняет stdout.

### Пример 1. Веб-сервер

Исходный файл: `examples/webserver.conf`.
Параметры сервера включают порт, число обработчиков, таймауты
и вложенные группы адресов. Пример содержит оба вида комментариев
и все пять операций.

```conf
' Конфигурация веб-сервера
<!--
  Порт, таймауты и группы адресов.
  В выражениях используются ранее объявленные константы.
-->
service: [[Сайт учебной группы]];
port: 8080.0;
workers: 4.0;
base: 2.5;
timeout: $* base workers$;
retry: $+ base 1$;
budget: $- timeout base$;
share: $/ timeout workers$;
capacity: $pow workers 2$;
hosts: {[[127.0.0.1]], [[localhost]]};
groups: {{[[api]], [[admin]]}, {[[static]]}, {}};
```

Запуск:

```sh
./run.sh < examples/webserver.conf
```

Фактический результат:

```toml
service = "Сайт учебной группы"
port = 8080.0
workers = 4.0
base = 2.5
timeout = 10.0
retry = 3.5
budget = 7.5
share = 2.5
capacity = 16.0
hosts = [
    "127.0.0.1",
    "localhost",
]
groups = [
    [
        "api",
        "admin",
    ],
    [
        "static",
    ],
    [],
]
```

Для сохранения результата:

```sh
./run.sh < examples/webserver.conf > webserver.toml
```

### Пример 2. Автоматизированная теплица

Исходный файл: `examples/greenhouse.conf`.
Вычисляются средняя температура, температурная разница, интервал полива
и площадь. Расписание содержит выражения внутри вложенных массивов.

```conf
' Конфигурация автоматизированной теплицы
<!-- Массивы описывают зоны, уставки температуры и интервалы полива. -->
name: [[Теплица № 13]];
day: +24.0;
night: 18.0;
offset: -0.5;
average: $/ $+ day night$ 2$;
delta: $- day night$;
adjusted: $+ night offset$;
interval: $* delta 5$;
area: $pow 3.0 2$;
zones: {[[Рассада]], [[Зелень]]};
temperatures: {{18.0, 24.0}, {17.5, 23.5}};
schedule: {$* delta 5$, {$+ 10 2$, $/ 60 2$}, {}};
```

Запуск:

```sh
./run.sh < examples/greenhouse.conf
```

Фактический результат:

```toml
name = "Теплица № 13"
day = 24.0
night = 18.0
offset = -0.5
average = 21.0
delta = 6.0
adjusted = 17.5
interval = 30.0
area = 9.0
zones = [
    "Рассада",
    "Зелень",
]
temperatures = [
    [
        18.0,
        24.0,
    ],
    [
        17.5,
        23.5,
    ],
]
schedule = [
    30.0,
    [
        12.0,
        30.0,
    ],
    [],
]
```

### Демонстрация ошибки

В `examples/invalid.conf` пропущена запятая между элементами массива.

```sh
./run.sh < examples/invalid.conf
```

В stdout ничего не выводится. В stderr поступает:

```text
Ошибка: Строка 3, столбец 16: Синтаксическая ошибка.
ports: {8080.0 8081.0};
               ^
```

Код завершения - 1. Проверить его сразу после запуска: `echo $?`.
Томл-вывод не смешивается с диагностикой даже при ошибке в конце документа.
