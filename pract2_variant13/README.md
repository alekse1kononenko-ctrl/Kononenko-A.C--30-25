# Граф зависимостей NuGet — практическая работа 2, вариант 13

Python 3.10+, стандартная библиотека. Установка пакетов Python не нужна.

## Запуск

`./run.sh configs/nuget.xml`

`python3 -m unittest discover -s tests -v`

Этап 1 выводит проверенные параметры XML. Пути разрешаются относительно XML.
Обязательны package, repository, test_mode, version, output и ascii.
Логические значения: true/false. output должен иметь расширение .png.
В обычном режиме repository — NuGet V3 Service Index HTTP(S).
В тестовом режиме repository — существующий локальный файл.
Дополнительные параметры: framework (net8.0), reverse (false), scope.
Ошибки возвращают код 1, неверный синтаксис CLI — код 2.

## Получение зависимостей

Этап 2: `./run.sh configs/nuget.xml --stage 2`; параметры: `--stage 1`.
HTTP-клиент сам читает Service Index, выбирает PackageBaseAddress/3.0.0,
запрашивает версии и `.nuspec` указанной версии. Модули: urllib, json,
xml.etree.ElementTree. Сторонние средства получения зависимостей не применяются.

Группы не объединяются. Выбирается точная framework; для современного .NET —
ближайшая меньшая major-версия .NET, затем netstandard2.1/2.0, затем общая
группа. Для netstandard2.1 допускается netstandard2.0. Другие несовместимые
TFM вызывают ошибку. Это ограниченная политика, а не полная реализация
NuGet.Frameworks; для проверенных примеров используется точная net8.0.

Версии зависимостей: минимальная опубликованная версия, подходящая под
интервал NuGet. Поддерживаются открытые/закрытые интервалы, точная [v],
минимальная v и prerelease при явном указании в ограничении.
Плавающие версии и build metadata отклоняются явно.
Это граф требований манифестов, а не полный алгоритм restore проекта.

Источники протокола:
- https://learn.microsoft.com/nuget/api/package-base-address-resource
- https://learn.microsoft.com/nuget/reference/nuspec
- https://learn.microsoft.com/nuget/concepts/package-versioning

## Рекурсивный BFS и тестовый репозиторий

`./run.sh configs/cycle.xml --stage 3`

JSON содержит version и packages (отображение имени в список зависимостей):
`{"version":"1.0.0","packages":{"A":["B"],"B":["A"],"Z":[]}}`.
Имена соответствуют `[A-Z]+`. Все цели рёбер должны быть объявлены, повторы
ключей и рёбер запрещены. Пустой список сохраняет изолированную вершину.
Граф от корня включает только достижимые вершины; полный локальный репозиторий
доступен через LocalRepository.nodes().

visit_levels рекурсивно обрабатывает ровно текущий уровень FIFO-очереди,
поэтому все вершины уровня d предшествуют вершинам уровня d+1.
seen отмечается при постановке в очередь; ребро сохраняется независимо от seen.
Сложность O(V+E), память O(V+E), рекурсивный стек O(глубины).
Ограничения: 500 уровней, 10000 узлов; превышение вызывает ошибку, не обрезание.
Тесты различают BFS/DFS и проверяют реальные рекурсивные вызовы.

## Обратные зависимости

`./run.sh configs/reverse-shared.xml --stage 4`

Для локального файла исследуется весь репозиторий, включая недостижимые от
целевого узла пакеты. Сначала BFS строит полный граф, рёбра разворачиваются,
затем тот же рекурсивный BFS ищет всех зависящих от цели (прямо и транзитивно).
В выводе обратного графа стрелка означает «цель -> зависящий от неё пакет».
Цель не включается в список собственных обратных зависимостей даже при цикле.

Для NuGet глобальный поиск по всем опубликованным пакетам не реализуется:
V3 flat-container не предоставляет готовый полный обратный индекс.
Требуется явный scope — путь к JSON вида
`[{"package":"Microsoft.Extensions.Logging","version":"8.0.0"}]`.
Область поиска — транзитивное замыкание этих корней. Она всегда указана в выводе.
Без scope реальный обратный запрос отклоняется вместо ложного пустого ответа.
Параметр reverse=true включает этот режим также на этапе 3/5.

## Mermaid, PNG и ASCII

Итоговый режим: `./run.sh configs/nuget.xml` (по умолчанию `--stage 5`).
Для воспроизведения исторических режимов задайте `--stage 1` ... `--stage 4`.
Этап 4 всегда выполняет обратный поиск. На остальных этапах он включается XML
параметром reverse=true. ASCII отображается только на этапе визуализации.

Python 3.9+ достаточен для получения и построения графа; сборки не требуется.
Только для отрисовки требуется Node.js и Mermaid CLI:
`npm install -g @mermaid-js/mermaid-cli@11.12.0`.
Браузер отрисовки устанавливается штатным установщиком Puppeteer.
Если mmdc отсутствует в PATH, задайте MMDC — путь к исполняемому файлу.
MERMAID_PUPPETEER_CONFIG — необязательный путь к JSON с настройками браузера.
Программа не отправляет диаграммы внешним сервисам; Mermaid работает локально.

Mermaid `.mmd` сохраняется рядом с PNG из output. Стрелка обычного графа
означает «пакет -> его зависимость». Узел определяется парой (имя, версия);
разные версии одного имени сохраняются раздельно. Общие узлы объявляются
один раз, циклы не удаляются. Длинные идентификаторы переносятся по точкам.
ASCII использует +--, `-- и |; [cycle] — ребро к активному предку,
[shared] — ранее раскрытая общая вершина. Лимит ASCII — 20000 строк с ошибкой
при превышении, без молчаливого обрезания.
Отсутствие renderer, ошибка процесса или неверный PNG возвращают код 1.

## Проверки

Локальные: `python3 -m unittest discover -s tests -v`.
Сетевые (отдельно):
`python3 -m unittest discover -s tests -p integration_nuget.py -v`.
Ошибки всех основных настроек: `python3 tools/demo_errors.py`.
Для анализаторов требуется Python 3.10+. Статический анализ: установите `requirements-dev.txt`, затем выполните
`python3 tools/check_quality.py`. Эти библиотеки используются только для
анализа исходного кода и не участвуют в получении зависимостей.

Проверено на macOS, Python 3.9, Mermaid CLI 11.12.0 и .NET SDK 10.0.403.
Для net8.0 и версии 8.0.0 сравнение с project.assets.json и деревьями
`dotnet nuget why` дало одинаковые узлы и рёбра:
Logging — 6/7, Configuration — 3/3, DependencyInjection — 2/1 (узлы/рёбра).
`dotnet nuget why` показывает пути проекта к заданному пакету, а не полную
картинку всех зависимостей корня. Для полного сравнения проверены assets.
NuGet restore может объединять версии, применять direct-dependency-wins,
RID и другие правила проекта. Наш граф строит требования манифестов по рёбрам;
полная эквивалентность restore для произвольного проекта не заявляется.

## Модули и функции

- config: load_config читает и проверяет XML; validate_element/read_fields
  проверяют структуру; boolean/http_url/resolve_file/output_file — значения.
- versions: version_key/normalize сравнивают версии; bounds/interval/satisfies
  разбирают ограничения; choose выбирает минимальную подходящую версию.
- frameworks: canonical/validate_target нормализуют поддерживаемую платформу;
  select_group/fallback/modern_candidate выбирают единственную группу.
- nuget: fetch выполняет ограниченный HTTP-запрос; json_object,
  service_resources и manifest проверяют ответ; NuGetRepository.versions,
  resolve, dependencies, read_dependencies получают и кэшируют сведения.
- local: LocalRepository проверяет JSON; dependencies/nodes читают рёбра
  и все вершины; unique_object запрещает повторяющиеся ключи.
- graph: breadth_first/visit_levels — рекурсивный BFS;
  label/describe — воспроизводимый текстовый вывод.
- reverse: scope_roots читает область поиска; reverse_graph разворачивает
  рёбра; reverse_dependencies строит область и выполняет обратный BFS.
- visualize: diagram_label/mermaid создают текст, ascii_tree формирует дерево,
  render_png вызывает только отрисовщик, visualize сохраняет результаты.
- application: repository_for/settings/find_reverse/run связывают операции;
  main.main разбирает CLI, выводит диагностику и возвращает код завершения.

Функции снабжены docstring. Исходники, тесты и инструменты проверяются по
ограничениям задания: 1000 строк/файл, 80 символов/строка, 40 строк/функция,
7 аргументов и цикломатическая сложность не выше 10. Бинарные результаты,
отчёт, архивы, кэши и настройки редактора исключены из Git.
